# 資料撰寫與 MVP 設計指南（Phase 2）

## 2.1 文件撰寫

根據比賽要求，產出以下文件：

| 文件類型 | 說明 | 對應模板 |
|---------|------|---------|
| 作品說明書 | 最核心文件，包含問題陳述、解決方案、技術架構、商業模式 | TEMPLATES.md → 作品說明書大綱 |
| 簡報大綱 | 決賽簡報或 3 分鐘影片腳本 | TEMPLATES.md → Demo 腳本模板 |
| 競賽研究報告 | 內部使用，包含競品分析與得獎策略 | (自行產出) |
| 加分佐證文件 | GitHub 截圖、LinkedIn 頁面、輕量化說明等 | (依需求產出) |

**寫作原則**：
1. **開場震撼**：用數據或故事在 30 秒內抓住評審注意力。
2. **問題具體化**：描述用戶的真實場景，而非抽象概念。
3. **差異化清晰**：用一句話說明「為什麼是我們，不是別人」。
4. **可量化效益**：時間節省、成本降低、準確度提升等具體數字。

## 2.2 MVP / Prototype 參賽方法論

**核心理念**：以最小可行性產品（MVP）參賽，而非等待「完美產品」。

**MVP 參賽策略**：

1. **驗證假設優先**：先證明「有人需要這個東西」，再擴充功能。
2. **展示已完成的部分**：
   - 需求驗證（社群調查、訪談）
   - 技術選型與架構設計
   - 可運作的核心 Demo（即使只有一條 happy path）
   - UI/UX 設計稿或原型
3. **把「未完成」變成「有紀律的階段性開發」**：
   - Phase 1：MVP（驗證核心假設）
   - Phase 2：擴展（加入更多平台/功能）
   - Phase 3：規模化（商業化、國際化）
4. **技術驗證數據**：即使樣本小，也要呈現具體數字（如：「趨勢吻合度 85%」、「回覆延遲平均 1.2 秒」）。

## 2.3 Demo 網頁 / 簡報設計

**快速產出方式**：
- 用 HTML + Tailwind CSS 製作單頁 Demo（可部署到 GitHub Pages / Cloudflare Pages）。
- 用 Markdown + Marp / Reveal.js 製作簡報。
- 用螢幕錄製軟體錄製 3 分鐘介紹影片（YouTube 不公開連結）。

**設計檢查清單**：
- [ ] 是否能在 3 分鐘內說完核心價值？
- [ ] 視覺風格是否一致？
- [ ] 有沒有清楚的 Call to Action？
